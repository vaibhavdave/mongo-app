4. Simulate a failover

    

      This step happens outside the app, in your terminal: run
      docker stop replication-mongo1 (the current primary
      priority 2 node) while repeatedly clicking "Read messages"
      (secondaryPreferred) and "Insert" above. Reads should keep working
      throughout (secondaries stay readable); writes will fail for a few
      seconds during the election, then succeed again once mongo2 or
      mongo3 is elected primary. Check status afterward - the surviving
      node should now show PRIMARY. Run docker start
      replication-mongo1 to bring it back as a secondary.
